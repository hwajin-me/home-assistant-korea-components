# 실 API 및 설정 흐름 검증 (2026-09-21)

제공된 키는 프로세스 메모리에서만 사용했습니다. 이 문서와 테스트 fixture에는
인증키·쿠키·gate-token을 저장하지 않습니다. 공공데이터포털 및 카카오에 실제로
요청했으며 Home Assistant는 테스트 harness로 config flow 메서드를 실행했습니다.
실제 HA 프런트엔드 UI/운영 인스턴스에 설정을 설치한 검증은 아닙니다.

## 실제 응답으로 발견·수정한 문제

1. 일반 약국 상세 응답에 목록 응답의 `dutyEtc`가 없음.
   상세의 현재 기관명/주소로 목록을 재검색하고 HPID를 대조해 병합하도록 수정.
   같은 이름의 다른 약국을 선택하지 않으며 상세 값이 공통 필드에 우선합니다.
2. 카카오 `break_times_desc`가 `13:30 ~ 14:00 브레이크타임` 형태를 반환.
   기존 `휴게시간`뿐 아니라 `브레이크타임`을 지원해 정상 시간표가 unknown이 되던 문제 수정.
3. 동물병원 초기 요청이 HTTP 503 + JSON `OpenAPI_ServiceResponse` / 코드 `05` 반환.
   후속 요청은 정상 성공. HTTP 상태뿐 아니라 게이트웨이 코드·메시지를 보존하도록 수정.

건강약국의 공공 `dutyEtc`는 13:00~14:00, 카카오는 13:30~14:00이었습니다.
둘을 임의 병합하지 않습니다. 현재 센서 상태는 카카오 날짜별 시간표를 따르고
공공 안내문은 `public_notes`/`api_record`, 출처는 `opening_hours_source`에 노출합니다.
데이터 간 차이 및 실제 현장 운영 여부는 서비스 원천의 한계입니다.

위 계약은 `test_live_contract_regressions.py`의 오프라인 회귀 테스트로 재현합니다.
전체 테스트 687개 통과/23개 제외, 의료 관련 312개 통과 및 대상 모듈 문장/분기 100%.
